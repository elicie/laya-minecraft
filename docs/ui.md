# 마을 관제실 사용법

중앙 서버와 웹 화면을 실행한 뒤 개발 화면 `http://127.0.0.1:5173`을 엽니다.
빌드된 화면은 중앙 서버 `http://127.0.0.1:3001`에서 볼 수 있습니다.

Tailscale로 연결된 기기에서는 `http://gti12-1:5173`으로 접속할 수 있습니다.
UI 개발 서버는 `0.0.0.0:5173`에서 직접 접속을 받고,
API·SSE·3D 요청은 중앙 서버로 중계합니다.
원격 접속을 다시 설정할 때는 `.env`의 `UI_ORIGINS`에 사용하는 화면 주소를
쉼표로 구분해 넣고 중앙 서버를 재시작합니다. 예를 들어
`UI_ORIGINS=http://gti12-1:5173,http://gti12-1.tailc6b81b.ts.net:5173`입니다.
`npm run dev`로 UI와 중앙 서버를 함께 실행합니다.

1. **마을 설정**에서 월드·차원, 중심 좌표와 수평 반경을 정합니다. 수집과
   수확 목표에 사용할 공동 창고의 실제 블록 좌표도 지정합니다.
2. **봇 추가**에서 이름·서버·주 역할·허용 작업을 입력합니다. 접속 여부는
   봇의 실제 보고로 확인합니다. 봇 수가 늘어나면 목록과 작업 배정에 반영됩니다.
3. **목표 등록**에서 자연어를 입력하고 **목표 해석**을 누릅니다. 작업,
   수량, 목적지, 건축 설계나 농장 좌표를 확인·수정한 뒤 등록합니다.

**설계도 관리**에서 기본 설계나 저장한 설계를 복제한 뒤 이름·크기·목재,
바닥·벽·지붕·창문 재료와 가구를 바꿀 수 있습니다. 미리보기의 배치와 재료
수량을 확인하고 저장하면 건축 목표의 설계도 선택 목록에 나타납니다.
저장한 설계는 수정·삭제할 수 있으며 이미 등록한 목표는 등록 당시 배치를
유지합니다. 새 배치를 적용할 목표는 설계도를 다시 선택해 수정합니다.

일반 건물은 높이 3~4, 전망대는 3~16을 선택할 수 있습니다. 다리는 높이 1과
홀수 폭, 성곽은 15×15×8 크기를 사용합니다. 전체 부지와 관측 범위를 넘는
크기는 저장 전에 안내합니다. 상자·작업대·화로·침대·조명은 템플릿에서
허용하는 공간에 배치합니다. 다리는 실내 가구를 사용하지 않습니다.

예를 들어 `원목 32개 모아 줘`는 공동 창고에 이미 10개가 있으면 부족한
22개를 확보·입고하는 목표입니다. 완료 후 재고가 줄어도 완료 상태를 유지합니다.
`원목 32개 유지해 줘`는 재고가 줄면 다시 보충합니다. `밀 8개 수확해 줘`는
수확한 물품의 창고 입고까지 확인합니다. `주변 경비해 줘`는 경비를 계속
유지하며, 순찰 구간 하나의 도착을 전체 경비 목표 완료로 표시하지 않습니다.

지도나 봇 목록의 **보기**를 누르면 현재 목표·행동·판단 이유·체력·허기·
인벤토리와 실제 3D 화면이 열립니다. 선택한 봇 한 대만 관전하며, 다른 봇으로
전환하거나 상세를 닫으면 이전 관전을 해제합니다. 보고가 10초 이상 없으면
접속 이상과 지난 관측임을 표시합니다. 미관측 지형은 지도에 그리지 않습니다.

지도는 작은 보조 영역으로 표시하고, 봇 관찰 영역에 더 넓은 공간을 줍니다.
넓은 화면에서는 3D 화면과 체력·현재 작업·조작 버튼을 나란히 볼 수 있습니다.
작은 화면에서는 선택한 봇 상세를 맨 위로 옮겨 바로 보여 줍니다.

건설 목표의 **건설 위치**는 마을 중심과 명시 좌표가 없으면 **봇 주변에서
부지 찾기**로 시작합니다. 봇이 실제 지면과 공간을 확인하고 건설할 위치를
찾습니다. 원하는 위치가 있으면 **고정 좌표 지정**을 선택해 X·Y·Z 정수를
모두 입력하세요. 자연어에 지정한 좌표는 해석 화면에서 그대로 확인할 수
있습니다. 건설 조건이 부족하면 봇 상세에 대기 중 목표와 구체적인 이유가
표시되며, 위험 대응 중에는 현재 위험 대응 행동을 우선 표시합니다.

봇 상세에서 역할·허용 작업 변경, 일시정지·재개·제거를 요청할 수 있습니다.
기본은 **작업 예약**이며 **즉시 전환**은 현재 동작을 안전하게 멈춘 뒤 적용합니다.
**요청 접수**와 **적용 완료**를 구분하므로 최종 적용 상태를 확인하세요.

중앙 시스템과 화면의 연결이 끊기면 마지막 현황임을 표시하고 변경 요청을
잠급니다. 화면은 자동으로 재접속합니다. 봇과 중앙 시스템의 연결이 끊긴 동안은
일반 작업을 안전하게 멈추고 위험 대응과 기본 생존만 수행합니다.
