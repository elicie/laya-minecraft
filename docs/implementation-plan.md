# 구현 순서와 검증

공통 계약과 워크스페이스를 먼저 고정한 뒤 중앙 core, API와 프로세스 서버, Minecraft와 모델 어댑터, React UI를 별도 작업 트리에서 병렬 구현합니다. 기능별 테스트를 통과한 변경을 커밋하고 푸시하며 PR로 제공합니다. 통합 브랜치에서 연결과 실행을 검증합니다.

## 구현 단위

1. 공통 기반: TypeScript strict, contracts 런타임 스키마, 실행과 테스트 스크립트, 설정 예시.
2. Core: 동적 등록부, 목표와 작업 분해, 역할과 능력 배정, 예약, 관측 검증, 중단과 재시도, 상태 복원.
3. Server: HTTP/SSE, 명령 영속화와 실제 적용 추적, IPC 감독, 재시작, 로그 정리, 화면 중계.
4. Minecraft와 모델: 공개 API 기반 관측과 행동, 생존과 전투 대응, 안전한 취소, Laya 응답 검증과 fallback.
5. Web: 마을 중심 화면, 선택 봇 상세와 3D, 자연어 목표 미리보기, 봇과 목표·규칙 관리.
6. 통합: 실제 워커 연결, UI/API 흐름, 기능 지원 범위와 실행 문서, 회귀 검증.

## 검사 기준

| 검사 | 확인할 사항 |
| --- | --- |
| 타입과 빌드 | strict TypeScript, 서버 빌드, Vite React 빌드 |
| 계약 | 잘못된 메시지, 중복 요청, 버전과 시도 식별 검증 |
| Core 시뮬레이션 | 0·1·5·20 봇, 중복 배정 방지, 역할과 우선순위, 오래된 결과 무시 |
| 복구 | 중앙·봇 종료, 안전한 중단, 최대 5회 재시도, 불확실 결과 보류, 재시작 재관측 |
| 목표 | 총수량과 추가 수량, 창고 입고 증거, 일회성과 재고 유지 구분 |
| 전투 | 반격, 경비·사냥꾼 선제 대응, 지원과 퇴각, 생존 fallback |
| API | 명령 접수와 실제 적용 구분, 규칙 버전, SSE 재연결, 영속 상태 |
| UI | 빈 마을, 봇 선택과 화면 연결, 목표 수정·등록, 상태와 오류 표현 |
| 실제 Minecraft | disposable minecraft-laya-validation 포트25566에서만 수행 |

실제 월드 테스트의 관리 명령과 fixture는 포트25566 검사를 통과해야 실행합니다. 사용자의 생존 월드는 테스트 대상에서 제외합니다. 20개 가상 워커의 통과는 실제20봇의 성능 보장이 아니며 실제 연결 수와 관측한 지연을 별도로 보고합니다.

초기 버전의 지원 작업은 실행기와 검증기가 구현된 범위로 표시합니다. 지원하지 않는 대형 목표는 다른 작업으로 조용히 대체하지 않습니다. 모델 평가와 학습은 코드 검증과 별도의 작업으로 관리합니다.
