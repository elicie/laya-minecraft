# 체력·식량 회복

체력 6.33·허기 17은 기존 긴급 기준인 체력 6을 조금 넘어서 일반 작업을 허용했습니다. 그 결과 낮은 체력의 식량 탐색이 중앙 작업에 반복 양보했습니다. 현재는 지원 체력 기준(기본 10)보다 낮거나 기존 위급한 체력·허기 조건이면 회복 상태를 시작합니다.

회복 중에는 식량 확보·섭취와 서버의 실제 체력 회복을 우선하며, 실제 체력 20과 허기 18 이상을 확인한 뒤 일반 작업을 재개합니다. 위험 대응이 먼저이며, 일시정지나 중앙 연결 단절 중에도 기본 생존은 유지합니다. 정상 체력 20·허기 17인 봇의 일반 식량 탐색은 기존 작업 양보 정책을 유지합니다.

| 단계 | 실제 수행과 근거 |
| --- | --- |
| 먹을 것 확인 | 현재 인벤토리의 식품을 공개 API로 먹고 실제 인벤토리·허기 변화를 확인 |
| 창고 식량 회수 | 같은 월드·차원의 설정한 창고와 `take` 권한이 있으면 실제 상자를 열고 식품 1개를 회수. 상자·인벤토리 양쪽 수량으로 확인 |
| 자연 식량 확보 | 관측한 작물·멜론 등 식품 원천과 가능한 제작 경로를 사용. 사냥은 기존 위험 판단과 권한을 유지 |
| 실제 회복 | 허기가 충분하면 서버의 실제 자연 회복을 기다리며, 떨어진 허기를 다시 보충 |
| 대기·재개 | 식량을 확보하지 못하면 회복 우선권을 유지한 조건 대기. 실제 자원·재고·접근 지형·창고 내용이 달라지면 다시 확인 |

회복 상태, 식량 대기 근거, 관측 기록과 소진한 탐색 예산은 엄격한 메시지 계약으로 저장하고 워커 부팅 때 복원합니다. 체력이 이미 10을 넘어도 진행 중인 회복의 목표 20을 유지합니다. 보고 시각·시간 경과·자체 탐색 이동으로 새 예산을 발급하지 않습니다. 새 창고 입고는 실제 컨테이너 관측의 정렬·합산한 내용으로 비교합니다.

회복 진입과 일반 작업 배정이 겹친 거절은 안전하게 남은 작업을 보존하고 재시도 횟수를 소모하지 않습니다. 과거 이미 보류한 작업의 실패·재시도 기록은 자동으로 지우지 않습니다. 실제 먹을 수 있는 식량이나 안전한 접근 경로가 없는 상태를 확보·회복 성공으로 처리하지 않습니다.

## 실제 검증

`tests/health-recovery.live.test.ts`는 Docker의 공개 포트를 먼저 확인한 뒤 별도 `minecraft-laya-validation`(127.0.0.1:25566), 격리한 API·SQLite와 실제 fork 워커를 사용합니다. 체력 6.33·허기 17, 빈 인벤토리에서 식량 대기를 만들고 소진한 기록을 재시작 후 확인합니다. 실제 멜론 원천 블록이 등장한 뒤 채집한 식용 드롭을 먹고 체력이 회복되는 것을 확인합니다. 체력이 10을 넘은 중간 상태에서 한 번 더 재시작한 뒤 최종 체력 20·허기 19와 동일한 귀환 목표 완료를 확인했습니다. 1/1 통과, 일반 검사 413개·브라우저 20개·strict TypeScript 및 빌드도 통과했습니다.

원천 블록을 준비한 주간 구역이며, 최초 상태를 실제 피해·허기 효과로 만들고 자연 재생 설정으로 검증 시점을 통제합니다. 이후 식량 아이템이나 치유 효과는 지급하지 않습니다. 임의 생존 지형의 식량 존재나 야간 위협 속 성능을 보장하는 검증과 구분합니다. Mineflayer와 다른 외부 라이브러리를 수정하지 않았고, 모델 가중치 학습도 수행하지 않았습니다.
