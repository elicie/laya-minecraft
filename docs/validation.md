## 모델과 지원 범위

기존 Laya `/api/decide` 연동 검증은 실제 응답으로 실행 가능한 후보 선택을 확인한 범위였습니다. 이후 수행한 Qwen 가중치 학습·평가·제한된 운영 적용 결과는 아래 2026-10-16 기록과 `training/README.md`에 구분해 남깁니다. 응답 검증 실패나 시간 초과에는 코드 판단을 사용합니다.

건축의 실제 실행 검증은 cabin, warehouse와 cabin을 복제한 6×5×3 사용자 설계에 한정합니다. 기존 warehouse와 사용자 설계도 검증은 건축 재료를 준비한 fixture에서 수행했습니다. 이번 warehouse 전체 검증은 시작 인벤토리를 비우고 도구·건설 재료 지급 없이 실제 원천 자원의 채집·제작부터 완공·창고 연결·후속 입고까지 통과했습니다. 평탄한 주간 구역에 풀과 원목·돌·모래·석탄 블록을 준비하고 최초 체력·허기를 회복한 조건이며, 임의의 생존 지형이나 자유로운 야간 위협 속의 완공 성능 검증은 아닙니다. 별도의 빈 인벤토리 준비 검증은 원목 3개와 돌을 배치한 fixture에서 수행했습니다. 부지 정리는 별도의 울퉁불퉁한 흙·잔디 지형에서 도구와 재료 없이 시작해 실제 44개 변경과 전체 부지를 확인했습니다. 나머지 내장 설계는 구조·재료·완료 조건을 코드로 검사합니다. 자연 지형 정리는 최대 192개 변경과 확인된 얕은 지반을 대상으로 합니다. 자유형 설계 생성, 깊은 굴착·액체·중력 지형 정리와 실제 다수 봇 부하 검증은 추가 작업입니다.

자원 복구 변경에서는 `resource-recovery`, `empty-inventory`, `terrain` 실제 연결 테스트 3개를 다시 실행했습니다. 새 자원·식량 복구 fixture는 실제로 걸은 뒤 별도 자원을 노출하며, 클라이언트의 청크 캐시나 라이브러리 메서드를 바꾸지 않습니다. 기존부터 미관측이었던 청크를 로드한 검증으로 해석하지 않습니다. 노출된 자원의 실제 채집·섭취와 관측 증거를 확인한 범위이며, 임의 생존 지형에서 전체 목표를 완수하는 성능 검증은 아닙니다.

## 재실행

전투·사망 복구는 `combat-recovery`와 `survival-recovery` 실제 연결 테스트
3개로 검증했습니다. 적은 제어된 `NoAI` 개체이며, 사망은 해당 적에 귀속된
실제 서버 피해 명령으로 발생시켰습니다. 사망 사실과 위험한 회수 보류를
저장한 후 위협을 제거하고 재시작했으며 사망 후 재료를 지급하지 않았습니다.
일반 밤 환경에서 적이 자유롭게 공격하는 생존 성능 검증과는 구분합니다.
퇴각 검증도 실제 이동·높이 차·엄폐와 지형 보존을 대상으로 합니다.

창고 없는 수집은 `collect-inventory` 실제 연결 테스트로 별도 검증했으며
전투·사망 복구 변경을 통합한 뒤에도 같은 시나리오가 통과했습니다.

```bash
npm test
npm run build
npx playwright install chromium
npm run test:web
MC_HOST=127.0.0.1 MC_PORT=25566 npm run test:live
```

자원 복구와 관련 회귀만 실행하려면 `MC_HOST=127.0.0.1 MC_PORT=25566 npm run test:live -- resource-recovery empty-inventory terrain`을 사용합니다.

이번 창고 전체 검증은 `MC_HOST=127.0.0.1 MC_PORT=25566 npm run test:live -- warehouse-bootstrap`으로 다시 실행합니다. 원천 자원 외에 도구·건축 재료를 지급하지 않으며 일반 테스트 실행에는 포함하지 않습니다.

저체력의 실제 회복은 `MC_HOST=127.0.0.1 MC_PORT=25566 npm run test:live -- health-recovery`로 실행합니다. 시작 상태를 실제 피해·허기 효과로 만들고, 이후 식량 아이템이나 치유 효과를 지급하지 않습니다. 실제 멜론 블록의 등장과 서버 자연 재생 설정을 통제해 식량 조건 변화·중간 회복과 재시작을 분리 검증하며, 마지막에는 자연 재생 설정을 복원합니다.

자원 복구를 운영 봇에 반영할 때 같은 창고 목표 ID·입력·세대 8과 당시 인벤토리를 보존했습니다. 실제 정상 이동과 재관측을 확인했고, 조기 종료된 체크포인트의 원점·이미 사용한 탐색 2회를 유지한 채 남은 후보를 확인해 5회에 도달했습니다. 이후 정상 플레이 중 스켈레톤 전투와 재생성 보고가 있었고 인벤토리가 달라졌습니다. 최신 창고 작업은 건축 위치 접근 조건을 기다리며, 조약돌 탐색의 소진 기록도 유지됩니다. 운영 창고가 완성된 것으로 처리하지 않았으며, 지형이나 아이템을 관리 명령으로 바꾸지 않았습니다.
