# 구현 검증

2026-10-10 기준으로 소스 검증과 실제 Minecraft 동작을 구분해서 기록합니다. 실제 Minecraft 검증 대상은 Docker `minecraft-laya-validation`, `127.0.0.1:25566`, Java 1.21.1입니다.

## 자동 검사

- 일반 테스트 232개 통과. 실제 연결 테스트는 아래 실행 범위와 별도로 기록합니다.
- strict TypeScript 검사와 서버·Vite React 빌드.
- 계약, 목표 분해·배정·예약·실제 결과 확인, 최대 5회 재시도, 오래된 메시지 차단, 재시작 복원 검증.
- 0·1·5·20개의 가상 워커로 동적 등록과 중복 실행 방지 확인.
- HTTP/SSE·SQLite·프로세스 감독·명령 중복 방지와 실제 적용 확인.
- Playwright 시나리오 17개: 목표 미리보기·수정, 하나의 viewer 전환, 오래된 관측 표시, 빈 마을·설정, 모바일 조작, 유휴 연결, 긴 활동 기록, 건축·수확 입력, HTTP 환경에서 viewer 재연결, 주변 건설 부지·고정 좌표 검증, 유휴 봇의 작업 대기 사유, 실제 부지 정리 진행과 건축 단계 구분, 설계도 저장·수정·삭제와 실제 적용 확인·목표 선택, 기본 설계 보호와 잘못된 크기 입력. 인벤토리 슬롯·장비·묶음·핫바·도구 상세와 실시간 이동, 미관측·빈 슬롯·지난 관측 구분, 320·375px 모바일의 9열 배치와 상세 표시를 포함합니다.
- 주변 부지 탐색의 실제 블록·접근 증거 검증, 같은 목표의 건설 단계 전환, 건축 조건 대기의 실제 변화에 따른 재개. 기본 탐색은 제한된 자연 지형 정리 계획을 먼저 평가하고, 계획이 없으면 부지 접근을 최대 2회·총 10초로 제한합니다. 진행 중인 20초 이동을 포함하면 약 30초 이내에 대기로 전환합니다. `allowPreparation: false`인 탐색 전용 목표는 기존 8회·60초 제한을 사용합니다.
- 지형 정리 계획의 실제 변경 전 관측, 시설·작물·액체·중력 블록 보존, 빈 동굴·미관측 지반 거부, 봇 발판 보호, 변경 수량과 접근로 범위 제한. 중단 뒤 실제 변경 결과로 남은 부분을 재개하며, 채운 흙의 자연 잔디 재성장을 허용합니다. 준비 결과를 검증한 뒤에도 건축 목표는 별도의 설계도 완료 관측을 요구합니다.
- 사용자 설계의 크기·재료·가구 검증과 미리보기, 기본 설계 복제 시 동일 배치 보존, 설계도 API와 저장·재시작 복원. 수정·삭제 후 기존 목표의 고정한 버전 유지, 관측에 첨부한 다른 정의 거부와 모델이 반환한 임의 배치 차단을 검사합니다.
- 인벤토리의 실제 46개 슬롯과 분리된 묶음, 선택한 핫바, 방어구·보조 손·제작 슬롯 검증. 열린 상자의 플레이어 영역만 반영하고 비워진 칸과 커서 상태를 확인합니다. 표시 이름·내구도·마법 부여를 공개 아이템 정보에서 읽고, 슬롯 미관측과 빈 인벤토리를 구분합니다.
- 빈 인벤토리에서 관측된 참나무·자작나무를 골라 작업대와 곡괭이를 준비하는 회귀 검사. Java 26.1의 실제 전체 목재 레시피 데이터로도 검사하며, 중간 제작에서 소비한 판자의 보충을 확인합니다.
- 체력·허기가 위급할 때 작업을 배정하거나 재시도를 소모하지 않고, 식량 확보와 실제 체력 회복 뒤 같은 작업을 재개하는 검사. 생존 상태가 이전 건설 대기 사유에 가려지지 않는 UI 검사.
- 설치된 Mineflayer 4.39.0 소스 무결성 확인. 프로토콜 767의 실제 레시피 패킷 1,290개 해석·재직렬화 확인.

자동 UI 시나리오는 테스트용 API를 사용합니다. 가상 20봇 검증으로 실제 20봇의 성능이나 Minecraft 서버 용량을 보장하지 않습니다.

## 실제 연결

실제 실행 검증은 별도 테스트 구역에서 재료·지형·성숙한 작물·동물을 준비해 수행합니다. 전체 생존 월드에서 재료 없이 시작하는 자율 발전 검증과는 범위가 다릅니다.

| 대상 | 확인 기준 |
| --- | --- |
| 수집·입고 | 창고 원목 10개에서 부족한 22개를 실제 수집·입고해 총 32개 확인 |
| 제작 | 원목 2개로 판자 8개를 제작하고 실제 인벤토리 수량 확인 |
| 빈 인벤토리 준비 | 원목 3개를 실제 채굴·회수해 작업대와 나무 곡괭이를 만들고, 원래 돌 위치로 돌아가 조약돌 1개 채굴·획득 확인 |
| 부지 정리 | 빈 인벤토리로 갇힌 발판에서 시작해 자연 지형 24곳을 깎고 얻은 흙으로 20곳을 메움. warehouse 기초·전체 빈 공간·출입로, 원래 발판 보존과 실제 입구 도착 확인 |
| 농사 | 물·경작·씨앗 설치, 성숙 작물 수확·재심기와 실제 창고 입고 확인 |
| 건축 | cabin 설계의 실제 블록과 가구 상태 확인; 주변 지면에서 부지 탐색 후 warehouse 136개 블록과 가구 상태, 건물 밖 지면으로 종료 확인 |
| 사용자 설계도 | API로 등록한 6×5×3 설계의 바닥·벽·지붕·창문과 가구 제외를 실제 96개 블록으로 확인. 설계도 수정·삭제 후에도 고정한 버전으로 건축 목표 완료와 건물 밖 지면 이탈 확인 |
| 인벤토리 | 실제 46개 슬롯의 흙 64+47개, 방어구·보조 손·선택한 핫바, 제작 칸·커서와 열린 상자의 플레이어 영역 확인. 이름이 지정된 곡괭이의 내구도 243/250과 효율 II 확인 |
| 번식 | 기존 동물과 구분되는 새 어린 개체 확인 |
| 경비·위험 대응 | 채집 역할이 공격받았을 때 반격하고 서버의 적 사망 이벤트 확인 |
| 중단 | 진행 중인 생존 대기 작업을 취소한 뒤 실제 중단 보고와 이동 정지 확인 |
| 중앙 실행 | HTTP 목표 → 작업 배정 → fork IPC → 실제 관측 → 완료, 일시정지·재개·제거와 프로세스 종료 확인 |
| UI·3D | 실제 봇 상태, WebGL 지형, viewer 중계와 일시정지·재개·제거 확인 |

안전한 중단은 실행이 멈췄다는 증거를 확인합니다. 섭취나 설치의 결과를 확정할 수 없는 경우에는 불확실 상태를 보류하며 다른 봇에 작업 소유권을 즉시 넘기지 않습니다.

## 모델과 지원 범위

기존 Laya `/api/decide` 서버의 실제 응답으로 실행 가능한 후보 선택을 확인했습니다. 모델 가중치 학습, 학습 전후 성능 평가, 역할별 모델 품질 평가는 수행하지 않았습니다. 응답 검증 실패나 시간 초과에는 코드 판단을 사용합니다.

건축의 실제 실행 검증은 cabin, warehouse와 cabin을 복제한 6×5×3 사용자 설계에 한정합니다. warehouse는 테스트 서버에 재료를 준비한 뒤 실제 주변 부지를 탐색하고 건설하는 흐름을 검증했습니다. 사용자 설계도 검증도 건축 재료를 준비한 fixture에서 수행했습니다. 빈 인벤토리 준비 검증은 원목 3개와 돌을 배치한 별도 fixture에서 수행했습니다. 부지 정리는 별도의 울퉁불퉁한 흙·잔디 지형에서 도구와 재료 없이 시작해 실제 44개 변경과 전체 부지를 확인했습니다. 재료 없이 전체 warehouse를 완성하는 생존 검증은 수행하지 않았습니다. 나머지 내장 설계는 구조·재료·완료 조건을 코드로 검사합니다. 자연 지형 정리는 최대 192개 변경과 확인된 얕은 지반을 대상으로 합니다. 자유형 설계 생성, 깊은 굴착·액체·중력 지형 정리, 사망 물자 자동 회수와 실제 다수 봇 부하 검증은 추가 작업입니다.

## 재실행

```bash
npm test
npm run build
npx playwright install chromium
npm run test:web
MC_HOST=127.0.0.1 MC_PORT=25566 npm run test:live
```

관리용 테스트를 실행하기 전에 검증 컨테이너와 포트 바인딩을 확인합니다. 사용자 생존 월드는 fixture 대상으로 사용하지 않습니다.

인벤토리 검증만 다시 실행하려면 `MC_HOST=127.0.0.1 MC_PORT=25566 npm run test:live -- inventory-observations`를 사용합니다. 운영 중인 `LayaTest01`에는 재연결 후 읽기 전용 보고로 실제 흙 두 묶음 64·47개와 나무 곡괭이 내구도 37/59가 전달되는 것을 확인했습니다. 운영 월드에 관리용 아이템을 지급하거나 슬롯을 수정하지 않았습니다.
