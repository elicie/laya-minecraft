# 중앙 구조와 운영 정책

한 컴퓨터에서 중앙 서버와 봇별 프로세스로 시작합니다. 중앙 서버는 목표, 계획, 작업 상태, 자원 예약과 배정을 관리하고 봇은 관측과 실행을 담당합니다. 봇 등록부를 기반으로 동작하며 특정 이름이나 고정 봇 수에 의존하지 않습니다.

## 책임

| 경로 | 책임 |
| --- | --- |
| packages/contracts | 공유 타입, 런타임 검증, 메시지와 API 형식 |
| packages/core | 월드 관측, 목표 분해, 선행 조건, 작업 상태, 역할과 능력 기반 배정, 예약, 결과 검증, 복구 |
| packages/minecraft | Minecraft 연결, 관측, 공개 API를 통한 행동, 즉시 생존과 전투 대응 |
| packages/models | Laya의 제한된 행동 선택, 자연어 목표 해석, 응답 검증 |
| apps/server | HTTP, SSE, 봇 프로세스와 IPC, 영속화, 3D 화면 연결 |
| apps/web | 마을 전체 현황, 목표 입력과 수정, 봇 선택과 상세 화면, 규칙 관리 |

Core는 Mineflayer, HTTP, DB에 직접 의존하지 않고 입출력 포트를 주입받습니다. HTTP 요청 접수, 봇의 작업 수락, 실행 시작, 실제 적용과 결과 검증을 구분합니다.

## 확정한 정책

- 위험 대응, 기본 생존, 사용자 목표, 여유 봇의 자율 마을 발전 순으로 처리합니다.
- 주 역할을 우선하며 허용된 다른 작업을 지원합니다. 사용자가 선택한 봇이 수행하기 어려우면 허용된 다른 봇으로 재배정합니다.
- 경비병과 사냥꾼은 마을이나 동료를 위협하는 적에 선제 대응합니다. 다른 역할도 공격받으면 반격하며, 불리하면 지원을 요청하고 퇴각합니다.
- 응급 행동은 봇의 로컬 실행기가 즉시 판단합니다. 중앙 또는 모델 응답을 기다리며 피격을 방치하지 않습니다.
- 일반 작업은 봇당 하나만 실행합니다. 응급 중단은 실패 재시도 횟수에 포함하지 않습니다.
- 사용자 작업은 기본 예약합니다. UI의 즉시 전환은 현재 작업을 안전하게 중단하고 실제 변경과 체크포인트를 확인한 뒤 적용합니다. 기존 작업은 조건을 재확인하고 남은 부분을 자동 재개합니다.
- 제거 요청은 현재 작업의 중단, 결과 확인, 연결과 프로세스 종료 확인을 거친 뒤 완료합니다. 남은 작업을 재배정합니다.
- 일시적 실행 오류는 초기 실행 이후 최대 5회 재시도하고 보류합니다. 이미 발생한 효과를 확인한 뒤 재시도하며, 결과가 불확실하면 보류합니다.
- 상태는 1초마다 보고합니다. 서버 수신 기준 10초간 보고가 없으면 접속 이상을 표시합니다. 이 표시만으로 작업 소유권을 다른 봇에게 넘기지 않습니다.
- 중앙 연결이 끊기면 일반 작업을 안전하게 중단하고 위험 대응과 기본 생존만 수행합니다.
- 모델이 실패하거나 유효한 행동을 내지 않으면 검증된 코드 행동을 사용하고, 가능한 행동이 없으면 대기합니다.
- 재시작 시 설정과 목표를 복원하고 실제 월드 관측으로 검증한 작업을 자동 재개합니다. 사용자가 정지한 봇은 정지를 유지합니다.
- 운영 로그는 최근 30일을 보존합니다. 학습 데이터와 평가 증거의 보존은 별도로 관리합니다.

## 마을과 자원

UI에서 서버와 차원, 마을 중심 좌표와 수평 반경을 지정합니다. 자율 발전은 해당 마을의 식량, 농장, 주거, 창고, 방어 시설을 대상으로 합니다. 건축 전체 배치는 마을 범위 안에 있어야 합니다. 자원 수집과 사냥은 해당 작업의 이동 정책에 따라 밖에서 수행할 수 있습니다.

마을 범위나 필요한 창고가 없으면 해당 작업은 조건 대기합니다. 범위를 줄여 진행 중인 자율 건축이 제외되면 안전하게 중단하고 다시 계획합니다.

주변 건설 부지는 탐색 → 부지와 접근로 정리 → 지면 재확인 → 건축 순서로 준비합니다. 이미 사용할 수 있는 평지는 정리 단계를 건너뜁니다. 빈 평지가 없을 때는 관측한 자연 지형을 깎고 낮은 곳을 흙으로 메우는 계획을 제안합니다. 자연 풀과 고사리는 정리할 수 있습니다. 중앙은 변경 범위와 실제 관측을 검증하고 작업 구역을 예약한 뒤 정리를 배정합니다. 기존 건물·창고·작물, 액체와 불안정한 지형은 보존합니다.

부지 준비와 건축은 같은 목표의 서로 다른 단계입니다. 정리 완료만으로 건축 목표를 완료하지 않으며, 실제 기초 지면과 빈 건축 공간, 출입 경로를 확인한 뒤 설계도를 실행합니다. 중단 뒤에는 실제 블록 상태로 남은 정리 작업을 계산합니다.

수집은 지정한 공동 창고의 총수량을 기준으로 완료합니다. 창고 원목 10개에서 “원목 32개 모아”는 22개를 추가 확보하고 운반합니다. “추가로 32개”는 새로 확보할 수량을 따릅니다. 창고가 아닌 봇 인벤토리에서 발견된 물자는 운반 단계가 남아 있습니다.

“모아”는 일회성 목표로 완료 후 종료합니다. “유지”는 지속 목표로 재고가 줄면 다시 보충합니다. 자율 마을 발전은 유지 목표를 만들 수 있으며 사용자 목표가 우선합니다.

## 데이터와 상태

Agent는 등록된 봇 설정이고 AgentSession은 실행과 연결의 세션입니다. Goal은 원하는 결과이고 Task는 배정할 실행 단위입니다. TaskAttempt는 특정 세션에서 수행하는 시도입니다. Reservation은 해당 시도의 자원이나 작업 구역 소유권입니다. Observation은 관측된 사실이고 Event는 의미 있는 변화 기록입니다.

일반 흐름은 대기 → 배정 → 수락 → 실행 → 검증 → 완료입니다. 조건 대기, 응급 중단, 사용자 정지, 재시도 대기, 결과 불확실 보류를 별도 상태로 유지합니다. 타임아웃이나 예약 만료만으로 이전 실행이 종료됐다고 판단하지 않습니다.

봇의 성공 보고 뒤 중앙이 관측으로 완료 조건을 검증합니다. 수집은 창고 수량, 건축은 설계도 블록과 설비, 제작과 제련은 산출물, 운반은 출발지와 목적지의 변화로 확인합니다. 처치 목표는 실제 사망 확인, 식량 목적의 사냥은 전리품과 입고까지 확인합니다. 생존, 경비, 따라가기, 재고 유지는 지속 목표로 표시합니다.

## Laya와 UI

Laya는 관측과 허용된 후보를 입력받아 행동을 선택합니다. 자유 형식 답변을 실행 코드로 평가하지 않습니다. 중앙은 응답 형식, 현재 조건과 정책을 검증합니다. 기본 전투와 생존은 코드 행동으로 유지할 수 있습니다.

첫 UI 화면은 마을 지도, 전체 봇과 목표 현황입니다. 선택한 봇에 상세 행동, 판단 이유, 체력, 허기, 인벤토리와 3D 화면을 연결합니다. 자연어 목표는 구조화된 해석 결과를 확인하고 수정한 뒤 등록합니다. 요청 중과 실제 적용 완료, 접속 이상과 오래된 관측을 구분합니다.

로그 저장이나 정책 수정은 모델 학습이 아닙니다. 모델 가중치를 학습한 경우에만 사용한 데이터, 모델 버전과 별도 평가 결과를 기록합니다.
